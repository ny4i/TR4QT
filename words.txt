  Why Do the Factory Pattern NOW?

  ✅ Advantages

  1. Only 3 contests to refactor - Much easier now than with 20+ contests later
  2. Establishes the pattern early - Future contests follow the template
  3. Clean architecture - Separation of concerns from the start
  4. Self-documenting - Each contest declares its own metadata
  5. Type-safe - No string matching, factory returns ContestBase*
  6. Automatic UI updates - New contest appears in chooser automatically
  7. No scattered logic - All contest info lives in the contest class

  ❌ No Real Disadvantages

  1. Small upfront cost (~200 lines for factory + registry)
  2. Need to update 3 existing contests (minimal work, ~5 lines each)
  3. That's it!

  Proposed Contest Factory Design

  Here's what I recommend:

  1. Contest Metadata Structure

  Each contest provides metadata via static methods:

  class CQWWContest : public ContestBase {
  public:
      // Factory metadata
      static ContestMetadata getMetadata() {
          return {
              "CQWW",                          // Factory ID
              "CQ World Wide DX Contest",      // Display name
              {ModeType::CW, ModeType::SSB},   // Supported modes
              WA7BNM_ID_CW,                    // WA7BNM ID (CW)
              WA7BNM_ID_SSB,                   // WA7BNM ID (SSB)
              true,                            // Has separate CW/SSB contests
              "Last full weekend of November", // When it runs
              "https://www.cqww.com/"         // Website
          };
      }

      // Factory creation method
      static ContestBase* create(ModeType mode) {
          return new CQWWContest(mode);
      }
  };

  2. Contest Registry (Auto-Registration)

  class ContestRegistry {
  public:
      static ContestRegistry& instance();

      // Registration (called by each contest's static initializer)
      void registerContest(const QString& id, 
                          ContestMetadata metadata,
                          std::function<ContestBase*(ModeType)> factory);

      // Query
      QList<ContestMetadata> availableContests() const;
      ContestMetadata getMetadata(const QString& id) const;
      ContestBase* createContest(const QString& id, ModeType mode);

  private:
      QMap<QString, ContestEntry> m_contests;
  };

  3. Auto-Registration Macro

  // In each contest .cpp file:
  REGISTER_CONTEST(CQWWContest, "CQWW");

  // Expands to:
  static bool registered = []() {
      ContestRegistry::instance().registerContest(
          "CQWW",
          CQWWContest::getMetadata(),
          &CQWWContest::create
      );
      return true;
  }();

  4. Simplified ContestChooserDialog

  void ContestChooserDialog::populateContestTypes() {
      // BEFORE: 10+ hardcoded lines per contest
      // AFTER: 3 lines total!

      for (const ContestMetadata& meta : ContestRegistry::instance().availableContests()) {
          for (ModeType mode : meta.supportedModes) {
              QString displayName = QString("%1 (%2)")
                  .arg(meta.displayName)
                  .arg(modeToString(mode));
              QString dataValue = QString("%1_%2")
                  .arg(meta.id)
                  .arg(modeToString(mode));
              m_contestTypeCombo->addItem(displayName, dataValue);
          }
      }
  }
